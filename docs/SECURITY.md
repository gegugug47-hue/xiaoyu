# 安全策略（SECURITY）

## 1. 支持版本

| 版本 | 安全更新 |
| --- | --- |
| `1.0.x` | 支持 |
| `< 1.0` | 不支持 |

只对最新发布版本提供修复。升级前请阅读 [CHANGELOG.md](../CHANGELOG.md) 与发布说明。

## 2. 私密上报漏洞

**不要**在公开 Issue、PR、讨论区或社交平台披露安全问题。

请使用 GitHub 的 **Security → Advisories → Report a vulnerability**（GitHub Security Advisory）私密提交。若入口不可用，请创建一个**不含漏洞细节**的 Issue，仅说明「需要私下联系」，由维护者建立私密渠道。

报告请尽量包含：

- 受影响版本、设备 Android 版本与 ABI；
- 复现步骤、预期结果与实际结果；
- 影响评估（可读取哪些数据、是否需要本地权限、是否需要用户交互）；
- 最小化证据：日志、截图或 PoC，**必须脱敏**；
- 你希望的署名方式（可选）。

维护者会尽快确认收到，评估后同步修复计划与披露时间。修复发布前请勿公开细节。我们不会对善意安全研究追究责任，但请遵守以下边界：只测试你自己的设备与账号，不访问、修改或泄露他人数据，不进行拒绝服务、社会工程或物理攻击。

## 3. 密钥与会话数据的处理原则

### 3.1 对本项目贡献者

- 永远不要把真实 API Key、网关 Token、Ollama 凭据写进代码、测试、示例、Issue、PR 描述或截图。
- 测试使用假值（如 `sk-test-not-a-real-key`）或环境变量，不要提交 `.env`、`key.properties`、`keys/`、`*.jks`、`*.keystore`、`*.p12`、`*.pem`。
- 提交前启用钩子：`git config core.hooksPath .githooks`；不要在失败时使用 `--no-verify`。
- CI 的 `security.yml` 会运行 gitleaks；如发现历史泄露，请立即在服务商侧吊销密钥，并联系维护者清理历史。
- 日志、诊断快照、错误信息中不得包含完整 API Key、Authorization 头或用户聊天原文。调试输出请截断并脱敏。

### 3.2 对使用者

- API Key 保存在设置表中，由 Android Keystore 的 AES-256-GCM 密钥加密；应用锁 PIN 只存 PBKDF2 摘要并用同一类密钥加密，且不进入备份。
- 数据库本身**不加密**，依赖 Android 应用沙箱。设备 root、调试版备份、恶意无障碍服务或物理取证都可能读取数据；高风险场景请使用独立设备或系统级加密。
- 应用锁开启后，通知与锁屏只显示「小鱼发来一条消息」，但已解锁的应用界面仍可被截屏 / 录屏；需要时请使用系统截屏限制或隐私屏幕。
- 本地备份默认是明文 ZIP，包含完整数据库；请存放在可信位置，或启用「用口令加密备份」。口令丢失无法恢复。
- Markdown 导出写入公共 `Download/小鱼导出/`，任何可读存储的应用都可能读取；分享前请检查并脱敏。
- 为支持局域网本地 AI 网关，App 允许明文 HTTP。请只在可信网络使用；公网服务必须使用 HTTPS，并确认证书校验未被绕过。
- 聊天内容会发送给你配置的模型服务商。请自行评估其隐私政策、数据留存与跨境传输风险；敏感内容不要发给不可信端点。
- 不要安装来源不明的「增强包」「破解版」APK。只从本仓库 Release 下载，并用 `SHA256SUMS` 校验：

```powershell
Get-FileHash .\app-v1.0.0-arm64-v8a.apk -Algorithm SHA256
```

## 4. 已知安全边界（非漏洞）

以下属于设计取舍，不属于需要私密上报的漏洞，但欢迎讨论改进：

- 数据库未整体加密（依赖系统沙箱）。
- 设置表加密依赖 Android Keystore；同一已解锁设备上的高权限恶意软件仍可能调用解密。
- 应用锁是应用内门禁，不是系统级安全容器；强杀、清除数据或卸载不受 PIN 保护。
- 明文 HTTP 仅用于本地网关。
- 备份不包含媒体文件；恢复后设置可能因 Keystore 变化而回退默认。
- 示例模式不产生网络请求，但也不提供真实模型能力。
- 模型输出可能包含错误或不当内容，这属于 [DISCLAIMER.md](DISCLAIMER.md) 覆盖的产品风险，不是安全漏洞。

## 5. 依赖与发布安全

- 依赖版本集中在 `gradle/libs.versions.toml`；升级依赖请在 PR 中说明变更与风险。
- 发布由 `.github/workflows/release.yml` 在 tag 上完成，签名材料仅存放在 GitHub Secrets，不进入仓库。
- Release 附带 `app-v<版本>-SHA256SUMS.txt`，请校验后再安装。
- 安全扫描在 push / PR 上运行 gitleaks；仓库不包含统计、广告或远程配置 SDK。

## 6. 事件响应

1. 确认报告并建立私密沟通渠道。
2. 评估影响范围与严重程度，必要时先发布缓解措施。
3. 在私密分支修复，补充回归测试。
4. 发布新版本与安全公告，按报告者意愿致谢。
5. 复盘并更新本文件或相关防护规则。

感谢你帮助保护所有使用者。
